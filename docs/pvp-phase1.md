# PvP Phase 1–4：同步房间、相对视角、时钟仲裁与连续对战

首页提供纵向 PvE、PvP、Sandbox 入口。首页和 PvP 大厅使用响应式布局；PvE 与沙盘保留原牌桌布局。

PvP 路由为 `#/pvp`、`#/pvp/room/123456`。昵称保存在 localStorage，每个页签的访客凭证与当前昵称保存在 sessionStorage。新玩家打开房间链接时先填写昵称。

## 房间登记

后端 `/api/rooms` 创建房间，`/{id}/join` 加入，`/{id}/state` 获取成员状态，`/{id}/leave` 解散房间，以上均为 POST。WebSocket `/api/rooms/{id}/ws` 替代轮询。服务器再次检查昵称、人数上限和同名玩家；访客凭证不广播给其他玩家。

WebSocket 连接后十秒内发送 `{type: 'join', client_id, nickname}`。原连接在线时拒绝相同凭证的第二条连接。操作消息为 `seat`（`seat: E/S/W/N`）、`ready`（`ready: boolean`）、`leave`、`ping`。服务端推送 `room_state`（含个人 `my_seat` 与服务器时间）、`pong`、`error`、`room_closed`。

按 E/S/W/N 首个空位入席；等待桌面固定左东、右西、上北、下南。真人人数达到上限后才补齐默认准备的 AI，AI 在开局前属于可替换占位。换座取消本人准备。全员准备且全员在线时进入三秒倒计时，统一使用服务器 `start_at` 毫秒时间戳；取消准备或换座终止倒计时。

倒计时结束只洗牌一次，物理东位（真人或 AI）为庄家。广播相同局号与公共牌局信息，各玩家只收到自己手牌，不下发其他手牌或牌墙顺序。暗杠的牌种与事件公开广播，所有模式固定按“牌背、明牌、牌背、牌背”展示。

牌桌显示坐标以自身风位旋转：自身在下、下家在右、对家在上、上家在左。手牌、副露、牌河、昵称与庄家标志共用同一映射；等待大厅仍保留固定物理座位。状态和操作始终使用物理 E/S/W/N，不随显示坐标改变。

所有客户端复用 PvE 财神仪式及 fetch 解码音效：中央亮相三秒，再用 600ms 飞入牌桌中央。客户端完成后发送 `opening_complete`（`game_id`）；服务器等待至少 3.6 秒且所有真人完成仪式才开放第一巡，防止 AI 提前行牌。

`game_action` 包含 `game_id`、`revision`、服务器生成的 `action_id`。服务器按连接所属座位验证合法操作、拒绝旧版本重放，权威处理摸打、吃碰杠、杠后补牌、抢杠与和牌响应，并沿用既有胡数与多方轧差结算。鸣牌优先胡、碰/杠、吃，同级按距出牌方次序处理。AI 按独立手牌策略行牌，不读取他人暗手。

服务器持有四方真人及 AI 的操作时钟与本局独立的 30 秒思考时间池。切牌先使用十秒，鸣牌或自摸先使用六秒；常规时间耗尽后无缝扣减时间池，操作完成立即暂停扣减。时间池也耗尽才自动摸打，或有胡自动胡、其余自动过；吃碰后没有摸牌，则切剩余手牌末张。同局不会补充时间池，下一局四方恢复三十秒。AI 从时钟启动起六秒出牌、三秒响应；PvE 切牌计算与思考等待并行，计算超过六秒则结果到达后立即行动。

`room_state.game` 的 `clocks` 和 `time_banks` 每秒按接收者视角裁剪后同步，行动时立即广播。客户端使用 `server_time` 校正绝对截止时间，在两次广播之间平滑显示倒计时；公开出牌行动者显示常规/加时阶段，低于三秒红色预警。鸣牌响应时仅本人收到个人时钟，自己的加时始终可见；对手加时仅在其公开出牌回合显示，其他时候统一隐藏，防止通过响应扣减反推手牌。高优先级碰/杠/胡尚未决定时，纯吃牌窗口挂起，常规时间和时间池都不扣减；所有抢断者放弃后才恢复。已成立的高优先级操作直接取消较低优先级窗口。无关广播、其他玩家操作和版本更新不会重置正在运行的时钟；财神仪式与结算期间不计时。PvE 保留四方公开计时，由本地状态驱动托管动作。

局后各真人发送 `next_hand`（`game_id`），确认人数广播给所有人，重复确认不累计；AI 不计入人数。全体真人确认才唯一生成下一局并重新播放财神仪式。庄家胡牌连庄，闲家胡牌或流局后按 E/S/W/N 轮庄；北位下庄回东位时完成一圈，“开始下一圈”同样需要全员确认。累计分数按原结算的净分累计，换局保留。物理座位与各客户端主视角不变。

PvP 不挂载 EV、向听、进张或危险度组件，也不请求推荐/威胁评估接口。右下角仅按公开余牌与副露数量显示单行基础对局进展。

任一真人离席、刷新或断线都会解散全房间，取消全部计时任务并清理牌局。其余在线客户端弹出“玩家 [昵称] 退出，房间已解散”并返回主页，不自动重连。入房失败仍留在 PvP 大厅供重试。此规则替代 Phase 1 的刷新恢复与房主交接行为。浏览器 Origin 单独校验，本地允许 localhost/127.0.0.1 预览端口。

房间号由服务器生成，SQLite 主键确保冲突重试。写事务保证并发加入不会超员；空房间关闭后仍保留号码，避免旧链接进入新房间。默认数据库为 `backend/data/rooms.sqlite3`，可用 `ROOM_DB_PATH` 指定持久化路径，数据库不提交到 Git。

`RoomsManager` 串行处理换座、准备、倒计时与广播。当前要求 **单 Uvicorn worker、单服务实例**（与现有 Render 启动命令一致）。连接、倒计时和牌局保存在内存中，水平扩容前需共享状态与发布订阅机制。房间号唯一性依赖统一的持久化数据库。Phase 1 数据库自动补齐准备与房间状态字段。

Vite `/api` 代理启用 `ws: true`。生产环境按 `VITE_API_BASE_URL` 自动使用远程 `wss://`；本地打包预览可在构建时临时设为 `/` 使用本地代理。

## PvP 结算、留谱与常亮

PvP 复用 `GameOverModal` 的 1080×560 双栏结算：左侧显示赢家昵称、胡数、番种、全部成牌面子/雀头、胡张与牌谱号，右侧四方显示本局及累计得分。未胡者只收到、展示原结算引擎真正计分的刻/杠与三元/自风雀头；无分顺子、客风对子及孤张不在结算中公开。暗杠保持三盖一明，原有支付和多方轧差算法不变。全员确认按钮显示实时人数，PvP 不提供历史/复盘入口。

每次真人获得新的可操作窗口，播放一次 Web Audio 双音“叮”；计时心跳、加时阶段切换和他家操作不重复播报，吃牌挂起时不提醒，恢复可操作时提醒。静音与音量遵循全局设置，不创建媒体播放标签或下载资源。

完成的 PvP 牌局由后端自动归档到独立 `pvp_game_records` 表，保存开局牌墙、合法操作序列、最终四家手牌/副露及完整结算，仅供后台留存。设置 `DATABASE_URL`（PostgreSQL）即使用现有云端数据库；本地默认 `backend/data/pvp_records.sqlite3`，可用 `PVP_RECORD_DB_PATH` 覆盖。事务保证幂等写入及 500 局 FIFO，重复广播不重复存档。此表不挂载复盘读取路由，与原 PvE 200 局牌谱隔离。保存失败会在下一局确认时重试，不直接丢弃上一局。

App 挂载及进入对局申请 Screen Wake Lock，页面恢复可见、获得焦点或用户操作时补申请，卸载时释放；不支持/被系统拒绝时正常降级。手机局域网访问需要浏览器认可的 HTTPS 安全上下文才能启用原生常亮；普通 IP HTTP 无此能力。手动锁屏或关闭页面仍遵循原有房间解散规则。

在上述独立服务下执行 `node scripts/pvp-settlement-smoke.mjs`，两个独立浏览器验证四方结算卡片、计分牌组过滤、胡张角标、全员确认、桌面/手机横屏排版、原生 Wake Lock 获取与恢复及行动提示音。截图在 `tests/artifacts/pvp-settlement/`。`tests/test_pvp_records.py` 验证 503 局裁减为最新 500 局、重复写入幂等与未胡者牌面隐私。

## 手机全屏与鸣牌隐私

手机点击准备/确认下一局时，同步复用 PvE 的原生全屏请求以保留用户手势；牌桌挂载再补请求。标准和 WebKit API 失败或不可用时，固定满视口的 `.viewport-wrapper` 使用 `100dvh`、9999 层级及非被动 touchmove 拦截阻止页面滚动，沿用原来的横屏旋转舞台。手动按钮支持退出和重新请求。离席卸载时清除兜底类名和触摸监听，不强制重新进入用户已退出的全屏。CSS 兜底占满浏览器提供的网页视口，不控制微信原生导航栏。

服务器鸣牌广播不包含其他座位的响应时钟、挂起状态或加时余额；前端也防御性过滤其他座位时钟及高亮。无剩余决策权的视角统一显示“等待其余玩家决策中...”及不绑定座位的公共六秒读秒，六秒后若仍在使用私人时间池则显示“加时等待”，直到服务器完成仲裁。旁观者不能从个人倒计时或余额变化识别吃/碰/杠/胡响应者。自己的六秒计时、加时、吃牌挂起、自动胡/过规则不变。

`node scripts/pvp-privacy-fullscreen-smoke.mjs` 使用三个独立浏览器：东家切五万、仅南家可碰，验证东/西两端 DOM 与 WebSocket 都没有南家的响应时钟或银行扣减；南家正常显示时钟并进入加时，过牌后统一等待消失并公开南家的出牌时钟。手机 Chrome 测原生全屏，微信 UA 加拒绝 Fullscreen API 的模拟测满视口兜底、手动切换及离席清理。截图保存于 `tests/artifacts/pvp-privacy-fullscreen/`。后端 `test_pvp_response_privacy.py` 和前端 `pvpFullscreen.test.js` 覆盖数据隐私、挂起恢复、WebKit、无 API、异步卸载及滚动监听清理。
