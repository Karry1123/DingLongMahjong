# 台州（黄岩）麻将切牌决策助手 (Mahjong EV Advisor)
## 产品需求文档 (PRD) — MVP 版本

---

## 1. 产品定位与目标用户

* **产品定位**：一款专为台州（黄岩）麻将定制的轻量级切牌决策辅助工具。通过计算打出每张牌后的和牌概率、进张数、台州特色胡头与番数倍增规则，得出量化的期望收益值（EV），辅助用户打出数学期望最优的一手牌。
* **目标用户**：
  * **麻将初学者/进阶爱好者**：对“得”（百搭）、“白板替身”及“硬胡/软胡翻倍”等规则难以即时计算最优收益的玩家。
  * **编程小白与个人开发者**：希望以麻将策略为切入点，完成自己第一个涵盖前端界面、后端 API 和概率算法的完整全栈项目。

---

## 2. 核心功能列表

### 2.1 MVP 必备功能（第一版交付范围）

* **基础场况输入**：
  * **指定“得”（百搭）**：支持在全牌 34 种牌型中选择 1 张作为“得”。
  * **白板替身逻辑切换**：若“得”非白板，系统底层自动将白板处理为被替代牌的原物理属性；若“得”为白板，则白板仅充当万能牌。
  * **庄家/闲家身份设定**：单选设置自身身份（影响庄家全额收支与闲家折半结算权重）。
* **手牌可视化点选录入**：
  * 支持 14 张手牌的点选录入（MVP 阶段简化为 14 张手牌纯手摸形态，副露面子暂视为手牌组合）。
  * 具备合法性约束校验（单种牌最多选 4 张，未满 14 张禁止计算，多选拦截）。
* **切牌 EV 评估引擎**：
  * 遍历当前 14 张牌中所有不重复的候选打出牌。
  * 对打出每张牌后的剩余 13 张牌进行算法评估：
    * 计算向听数（判断距离听牌、和牌的距离）。
    * 统计有效进张牌种类与剩余张数（默认基于剩余未知牌库均匀分布估算）。
    * 评估胡牌预估胡头（字牌/幺九暗刻加权） 与番数乘数（硬胡 $\times 2$）。
    * 输出综合打分值（EV 指数）。
* **决策结果输出与推荐**：
  * 排序展示候选打出牌列表。
  * 强制将综合得分最高的牌标红/高亮为“第一推荐切牌”，并附带简要收益解释（如：“进张面最广”、“保留硬胡机会”）。

### 2.2 后续演进功能（V2.0 / V3.0）

* 独立副露区录入（吃、碰、明杠、暗杠分开展示，精确计算明暗胡头）。
* 牌池与弃牌废牌过滤（录入三家已打出的牌，提高有效进张计算精度）。
* 闲家固有胡头差额折半互结计算。

## 3. 用户使用流程 (User Flow)
    [打开网页/App]
       │
       ▼
    [步骤 1: 基础场况设置] ──> 选择当盘“得”（财神）是哪张牌（如：5条）
                         ──> 选择当前身份：庄家 / 闲家
       │
       ▼
    [步骤 2: 录入当前手牌] ──> 在下方麻将牌选择区连续点击，选齐 14 张手牌
                         ──> 选错可单机手牌中的牌退回/删除
       │
       ▼
    [步骤 3: 触发计算]     ──> 点击底部的「智能推荐切牌」按钮
       │
       ▼
    [步骤 4: 结果展示]     ──> 页面顶部弹窗/吸顶展示最优解：“建议切出：[ X 牌 ]”
                          ──> 下方展示完整排序卡片列表，说明每张牌的听牌面、胡头潜力与综合 EV

## 4. 界面大致描述 (UI/UX 布局)

页面采用**单页流式布局 (Single-Page Dashboard)**，设计为响应式，适配移动端和桌面端：

* **顶部：场况控制条**
  * `当盘“得”（财神）`：卡片式选择器，默认展示为“白板”，点击可展开弹窗选取 1~9万、1~9筒、1~9条、东南西北中发白。
  * `自身身份`：分段开关按钮，切换 [ 庄家 ] 或 [ 闲家 ]。
* **中部：手牌与输入面板**
  * **已选手牌槽**：横向排布 14 个卡槽，放置已选中的麻将图标。未满时以虚线框占位，每张牌右上角带有移除角标。
  * **选牌键盘区 (Palette)**：
    * 分为四行：万字区（1-9m）、筒子区（1-9p）、条子区（1-9s）、字牌区（东/南/西/北/中/发/白）。
    * 每张按键展示该牌剩余可用计数（0~4），为 0 时置灰不可点。
* **底部操作区**：
  * 主操作按钮：「开始 EV 分析」（已选满 14 张时点亮为主要高亮色，未满置灰并附带提示“还需选择 N 张牌”）。
  * 次级操作按钮：「一键清空」。
* **结果展示区 (Analysis Result)**：
  * **推荐横幅**：以金黄色大卡片置顶：“最佳选择：打出 [ 1 万 ]”，并展示“预估 EV：+18.4 | 有效进张：12 张”。
  * **候选列表**：以列表形式自高到低排布其他候选切牌，每项标注对应进张数、听牌向听数与硬胡标识。

## 5. 技术难点预估与小白解决方案

| 技术模块 | 核心难点 | 小白简易应对方案 (MVP 策略) |
| :--- | :--- | :--- |
| **规则转换** | 白板替身与百搭逻辑耦合，容易造成牌面识别混乱。 | **预处理映射**：在数据进入判断逻辑前，将所有“白板”在内存数组中替换为被替代牌名；将所有“得”统一替换为一个特殊的全局代号（如 `JOKER`）。 |
| **和牌判定** | 包含 0~4 张百搭牌的 $4 \times 面子 + 1 \times 雀头$ 验证复杂度高。 | **DFS 回溯剪枝**：遍历所有可能的雀头对子候选，优先利用百搭补齐顺子/刻子，只要剩余百搭数量足以补全残缺面子即可判定合法。 |
| **EV 计算规模** | 完整期望值计算需要穷举所有摸牌与多步深搜，算法容易超时或把简易后端算崩。 | **一级向听静态估值近似**：<br>$$\text{Score} = (\text{有效进张数} \times \text{平均胡头得分}) - (\text{向听数} \times \text{惩罚权重})$$<br>若打出某张牌能使手牌保留硬胡条件（无须百搭辅助），直接将收益得分乘以 2（硬胡翻倍）。 |
| **工程架构** | 前后端通信及部署环境对零基础开发者门槛高。 | 采用 **Python FastAPI + 前端单 HTML（含 Vue CDN）** 单体结构，轻量且无需配置复杂的 Webpack/Vite 编译打包，本地一条命令即可运行。 |

## 6. 成功标准 (Definition of Done)

满足以下 4 点即判定第一版 MVP 构建成功：

1. **基本链路畅通**：前端单页能完整走完“选百搭 $\to$ 选 14 张手牌 $\to$ 后端异步计算 $\to$ 渲染推荐结果”全流程，单次分析耗时在 1.5 秒以内。
2. **白板替身逻辑正确**：设定 3 条为“得”，手牌录入 2条、白板、4条，系统能正确将其判定为一个有效顺子（2条-3条-4条）。
3. **决策倾向符合麻将常识与规则**：
   * 在手牌含有风牌无用孤张时，系统能将其排在推荐出牌前列；
   * 在听牌分支中，能够准确识别出“硬胡（番数翻倍）”方案相比于“软胡”所具备的更高收益权重。
4. **容错与鲁棒性**：未选满 14 张牌无法提交，单张物理牌输入不能超过 4 张，且百搭牌不可作为杠牌面子进行开杠计算。
